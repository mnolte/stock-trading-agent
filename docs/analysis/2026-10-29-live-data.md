Bug 1 (critical): trade-updates stream drops 100% of messages
alpaca.py:172 creates TradingStream(..., raw_data=True). With raw_data=True, alpaca-py's _cast returns the raw wrapper {"stream": "trade_updates", "data": {...}} (stream.py:136-139). parse_trade_update then reads raw.get("order", {}) at the top level of that wrapper — there is no order key there — so parse_order({}) hits raw["id"] → KeyError at alpaca.py:89.

Evidence: every trade update crashes with KeyError: 'id' — 29 today (bursts at 14:47, 15:46, 18:47 UTC), and every update since the first one on Oct 28 14:46. The SDK catches it, logs the ERROR, and reconnects — the message is never re-delivered.
