Confirmed bugs (root cause found, already fixed)
1. Model credentials lost on decide.reload() — fixed in 7c9b51d (18:48 today).
DecisionService.reload() rebuilt the client via make_model_clients(self.config) without the secrets store, so every adapter got MISSING_KEY. The Anthropic key save at 15:16 called _apply_keys → decide.reload(), which is exactly when the 401s began. For two full cycles the held positions HD and NKE got no model evaluation and no candidate was scored — broker-side stops remained the only protection. Shadow runs were unaffected (separate ProviderClients built with secrets). Recovery at 17:20 matches update_key being called on the key test. Worth noting: the failure mode was silent at cycle level — decisions recorded as no_call/model_error with no critical event or notification. Gap: a persistent auth failure across a whole cycle should raise a critical event, not just per-decision error rows.

2. Trade-updates envelope dropped every update since 28 Oct — fixed in deaa6fe.
Explains the stream_degraded critical at 13:51 ("no trade update within 120s of a fill") and why ACN's 13:34 fill was only caught by the 13:51 startup reconcile 17 min later.

3. check_clock 'AlpacaPaperBroker' object has no attribute 'get_clock' — fixed in deaa6fe.
Hourly WARNING from 28 Oct 13:22 through today 11:24; healthy since the 13:51 restart (offset 385ms, level ok).

Bugs / gaps still present
4. Premature fill notification (wrong qty). Notification 111 says "opened PG: 10 shares @ 162.85" — sent on the first partial-fill batch; the position is 12 shares. Notifications should wait for the order to reach terminal state / full fill.

5. Reconciliation cries wolf during normal partial fills. PG filled in four prints over 2.1s; DB fill-tracking ran ahead of Alpaca's positions endpoint, producing two critical qty_mismatch events (8 vs 10, then 10 vs 12) that self-resolved 1s later. Each fires a critical banner + ack flow. Suggest a grace window: only compare qty once the entry order is fully filled, or retry once before raising critical. Alert fatigue on a self-healing condition risks masking real mismatches.

6. Synchronous broker calls inside API handlers can hang for 87s. GET /api/positions and /api/risk-budget took 87,3xx ms at 00:48 (during the stream outage). These endpoints proxy live Alpaca reads; a slow broker stalls the UI. Consider a timeout + served-from-cache fallback.

7. tighten_stop silently no-ops on stale price. Cycle 255: model chose tighten_stop for HD (325.54), guard rewrote to hold with {"tighten_noop": true, "reason": "price_stale"} — correct conservative behavior, but it's invisible unless you read gates_result; no retry mechanism, and HD's quote had just fetched fine at 17:46:46 (IEX feed). Worth checking whether price_reason is too strict for IEX free-feed quotes, since this veto will recur.

8. Minor: GET /api/chart/ with empty symbol → 404 twice (17:13, 17:43). Rule 19 wants bad input to get 422 and never reach a handler; the frontend is also sending a request with an empty symbol.
